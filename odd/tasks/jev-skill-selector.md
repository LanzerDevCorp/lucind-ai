# Jev skill selector

## Objective

Let Jev (TypeSafe System One) decide which skills a lane worker loads before work, so the
orchestrator no longer reads `.atl/skill-registry.md` or writes `## Skills to load before work`
by hand. Experimental: raw probabilities are recorded per lane turn for later evaluation.

## Problem and why

The orchestrator resolves skills itself today (`plugin/claude-code/skills/lucind/SKILL.md`,
"Brief sections"). That costs parent context (the registry has 42 rows) and judgment on every
dispatch. A multi-label yes/no judgment per skill is exactly what Jev's Noul primitive does.

## Scope

- In: registry parser, plain-HTTP Jev client, selector, `lucind-ai skills select` subcommand,
  opt-in `dispatch --auto-skills` that injects the section and records `skills-<turn>.json`,
  docs.
- Out: making the selector the default; any authority beyond the skills section; changes to the
  user-global CLAUDE.md skill registry protocol (outside the repository).

## Decisions

- D1. Lives in the binary, not a hook or MCP: deterministic, testable, recorded next to the lane.
- D2. Candidates come from `<repo-root>/.atl/skill-registry.md` (gitignored, regenerated by
  `gentle-ai skill-registry refresh`). Jev only selects; it never invents paths.
- D3. One Noul per skill in one request (several skills may apply). Threshold 0.7 in code.
- D4. State: brief text, allowed edit surfaces, file extensions. Instructions say a coding
  subagent implements the brief and cannot open PRs, orchestrate, review or talk to the user, so
  orchestrator-only skills are rejected.
- D5. Fail open: any selector error dispatches without the section and warns on stderr.
- D6. API key from `TYPESAFE_API_KEY` only (the old `LUCIND_JEV_API_KEY` is read nowhere since
  `c8897c2`). Client hardening reused from the deleted `internal/router/jev.go`: no redirects,
  1 MiB body cap, https except loopback, no retries, key never logged.
- D7. The owner lifted the old D15 (herdr-agent-factory) restriction for this experiment: Jev may
  receive the brief text.

## Acceptance criteria

- `lucind-ai skills select --brief <file>` prints JSON with every registry skill, its
  probability and whether it passes 0.7.
- `dispatch --auto-skills` never fails because of the selector, never overrides an existing
  section, and records the decision per turn.
