# Agent Rules Generation

`lucind-ai` maintains a single, versioned rules source per workspace that generates agent instruction files (`CLAUDE.md`, `GEMINI.md`, and `AGENTS.md`) within the repository workspace. Rules are scoped to the repository and never written to user-global configuration directories.

## Source Format (`lucind-rules.md`)

The rules source is located at `<workspace-root>/lucind-rules.md` and is checked into version control alongside repository code (never placed under `.lucind/`, which is ignored working state).

The file is written in Markdown. Sections are defined by marker lines of the exact form:

```markdown
<!-- lucind:rules audience=<list> -->
```

where `<list>` is a comma-separated, no-spaces subset of:
- `orchestrator`
- `worker`
- `all`

### Syntax Rules and Validation

- The file begins with a section marker line. Any text before the first section marker is rejected with an error identifying the line number.
- `<list>` must contain at least one valid audience. Empty lists (e.g., `audience=`) or unknown audience identifiers are errors naming the line number.
- Spaces are not permitted in the audience list (e.g., `audience=worker, orchestrator` is invalid; use `audience=worker,orchestrator`).
- Duplicate audiences within the same marker (e.g., `audience=worker,worker`) are rejected with an error naming the line number.
- A source file with no section markers is an error.
- Section bodies run from their opening marker to the next marker or end of file.

## Audience-to-File Mapping

Each generated file is targeted to specific agent roles and starts with a role title:

| Output File | Audience Filter | Title | Intended Consumer |
|---|---|---|---|
| `CLAUDE.md` | `orchestrator`, `all` | `# Agent rules: orchestrator` | Claude Code orchestrator lanes |
| `GEMINI.md` | `worker`, `all` | `# Agent rules: worker` | Antigravity (`agy`) worker lanes |
| `AGENTS.md` | `worker`, `all` | `# Agent rules: implementers` | Implementer lanes (`opencode`, `cursor-agent`) |

Sections appear in the exact order in which they occur in `lucind-rules.md`.

In `CLAUDE.md`, the orchestrator rules explicitly specify that implementation delegation goes through the dispatcher:

```text
Delegation goes through the dispatcher: run `lucind-ai run --packet <file>`; never start ad-hoc agent processes for implementation work.
```

## Generated Marker

The first line of every generated file is a deterministic header containing the SHA-256 digest prefix (first 12 hexadecimal characters) of the source file:

```markdown
<!-- GENERATED by lucind-ai rules generate from lucind-rules.md (sha256:<first 12 hex of source hash>); do not edit, change the source and regenerate -->
```

All generated files share the exact prefix: `<!-- GENERATED by lucind-ai rules generate`.

## Safety Invariants

- **Hand-written Files are Never Overwritten**: If an existing target file (`CLAUDE.md`, `GEMINI.md`, or `AGENTS.md`) does not begin with the generated marker prefix (`<!-- GENERATED by lucind-ai rules generate`), it is treated as hand-written. `generate` will never overwrite or modify it, reporting `skipped_hand_written` with exit code 0.
- **Self-Hosting Repository Exemption**: This repository's own `CLAUDE.md` is hand-written and is therefore skipped when `lucind-ai rules generate` executes.
- **Symlink Protection**: If a target file destination is a symbolic link, `generate` does not follow the link; it treats the target as `skipped_hand_written`.
- **User-Global Directory Prohibition**: `rules init` and `rules generate` refuse to operate on any root directory that is, or is located inside, `$HOME/.claude` or `$HOME/.gemini`. Path comparisons occur after evaluating symbolic links (`filepath.EvalSymlinks`).
- **Atomic File Writes**: Target file writes are atomic. Content is written to a temporary file in the destination directory with permissions `0644`, then renamed into place. On any write or rename failure, temporary files are cleanly removed.
- **Idempotence**: Running `generate` multiple times against an unchanged source produces `unchanged` for existing generated files and makes no modifications to disk.

## CLI Commands

### Initialize Rules Source

```bash
lucind-ai rules init [--root <dir>]
```

Writes the default embedded rules template to `<root>/lucind-rules.md`.
- If `<dir>` is omitted, `--root` defaults to the git repository top-level (`git rev-parse --show-toplevel`).
- If `<root>/lucind-rules.md` already exists, `rules init` leaves the file untouched (never overwrites) and reports that it already exists.

### Generate Agent Instruction Files

```bash
lucind-ai rules generate [--root <dir>] [--check]
```

Reads `<root>/lucind-rules.md`, parses sections, and generates `CLAUDE.md`, `GEMINI.md`, and `AGENTS.md`.

Output per target:
- `<file>: written` — Target file was created or updated with new rules content.
- `<file>: unchanged` — Target file is already up to date with the source hash and content.
- `<file>: skipped_hand_written` — Target file does not begin with the generated marker or is a symlink; left unmodified.
- `<file>: stale` — Target file differs from what would be generated (only reported with `--check`).
- `<file>: missing` — Target file does not exist (only reported with `--check`).

### Exit Codes

- `0`: Success (including when targets are `skipped_hand_written` or `unchanged`).
- `1`: Error encountered (missing `lucind-rules.md`, forbidden root directory, invalid flags, not inside a git repository without `--root`, or when `--check` finds any `stale` or `missing` file).
