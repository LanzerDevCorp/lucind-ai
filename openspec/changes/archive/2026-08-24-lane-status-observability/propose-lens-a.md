# Proposal Lens A — Candidate & Approach: Lane Status Observability

## Selected Candidate & Approach

We select **Candidate 1: Wire existing metadata path + add PID sweep + structured telemetry, one PR**, confirming the user-selected direction from exploration (`openspec/changes/lane-status-observability/explore.md:58-66`). This delivers the complete six-item observability scope in a single coherent PR under `size:exception`:

1. **Wire Metadata Dispatch Path**: Update `internal/run/run.go:334-355` (`Execute`) and `internal/run/batch.go:184-200` (`ensureLaneFailed`) to invoke `deps.Ledger.UpdateLaneMetadata` (`internal/ledger/lanes_meta.go:39-83`) immediately after `RegisterLane`. Populate `LaneMetadata` (`internal/ledger/lanes_meta.go:20-32`) with `Model`, `Agent`, `Feature`, `SDDPhase`, `FanoutGroup`, `Change`, `AllowedPaths`, `Dependencies`, and `BodyDigest` from `packet.Packet`.
2. **Extend Frontmatter Parsing**: Expand `packet.Parse` (`internal/packet/packet.go:78-167`) to parse `sdd_phase`, `fanout_group`, and static `skill` keys alongside existing fields (`packet.go:94-138`). Propagate on-disk packet paths captured from `packetFlags` (`cmd/lucind-ai/cli.go:160-174`).
3. **Structured Telemetry Ingestion**: Extend `executor.ProgressEvent` (`internal/executor/executor.go:17-21`) and `ledger.LaneProgress` (`internal/ledger/progress.go:14-20`, `internal/serve/model.go:186-193`) with numeric `total_tokens`, `cost_usd`, and tool call metrics. Stream decoders for `agy` (`internal/executor/agy_stream.go:12-18,27-39`), `claude` (`internal/executor/claude_stream.go:17-36`), and `opencode` (`internal/executor/opencode_stream.go:100-120`) populate these fields alongside prose messages, while `cursor-agent` (`internal/executor/cursor_agent.go:1-60`) leaves them empty.
4. **SQLite Schema v7 STRICT Migration**: Introduce `migrateV6ToV7DDL` in `internal/ledger/schema.go:310-330` using the established create-copy-drop-rename pattern (`schema.go:182-219,221-308`) to add `pid` to `runs` (`schema.go:226-234`) and usage/tool columns to `lane_progress` (`schema.go:298-307`).
5. **PID-Based Orphan Reconciliation**: Store the driving runner PID in `RegisterRun` (`internal/ledger/runs.go:26-37`). Implement an orphan sweeper in `internal/serve` that runs at startup and periodically on a ticker, checking recorded PIDs and transitioning orphaned `running` lanes to `failed` with an `EventLaneNote` audit entry (`internal/ledger/lanes_meta.go:67-77`).
6. **Dispatched Packet Body Link**: Add a REST endpoint in `internal/serve` to serve the dispatched `.md` packet content by lane/packet ID, linked from dashboard cards (`internal/serve/static/app.js:529-545`, `internal/serve/model.go:162-184`).

This approach solves the problem: dashboard "Unavailable" states (`internal/serve/static/app.js:532-538`) exist because `UpdateLaneMetadata` has zero production callers (`internal/ledger/lanes_meta.go:39`, `explore.md:15-18`), and 25h+ stuck lanes occur because no runner PID is tracked in `runs` (`internal/ledger/runs.go:16-24`, `explore.md:49-54`).

## Conceptual Changes & Architecture Rationale

- **Schema v7 STRICT Rebuild (`internal/ledger/schema.go`)**: Both `runs` (`schema.go:226-234`) and `lane_progress` (`schema.go:298-307`) are STRICT tables. SQLite cannot widen STRICT tables or modify CHECK constraints in place (`schema.go:182-189,221-224`). Following `migrateV4ToV5DDL` (`schema.go:190-219`) and `migrateV5ToV6DDL` (`schema.go:225-308`), v7 builds `runs_new` and `lane_progress_new`, copies existing rows verbatim with `INSERT ... SELECT`, drops legacy tables, and renames the new tables into place. Combining `runs.pid` and `lane_progress` telemetry into a single v7 migration minimizes database lock churn and migration version bumps.
- **Static Orchestrator Attribution vs. Runtime Telemetry**: The new `skill:` packet frontmatter key (`internal/packet/packet.go:78-167`) is static metadata recorded by whichever orchestrator or skill generated the packet. Runtime "Skill" telemetry is deliberately avoided because non-Claude executors (`agy` on `gemini-3.7-flash-high`, `cursor-agent` on `cursor-grok-4.6-high`, `opencode` on `openai/gpt-5.6-sol`) lack Claude Code's Skill tool concept (`explore.md:42-47`). Live activity is represented through generic tool call counters (Read/Write/Edit) extracted from stdout stream records (`internal/executor/agy_stream.go:33-38`, `internal/executor/claude_stream.go:46-60`, `internal/executor/opencode_stream.go:115-120`).
- **Hybrid Metadata Persistence Pattern (`internal/ledger/lanes_meta.go`)**: Maintains the schema-v6 architectural distinction: queryable core columns (`model`, `agent`, `feature`) reside on the `lanes` table (`schema.go:249-251`), while extensible SDD dispatch attributes (`sdd_phase`, `fanout_group`, `change`, `skill`, `allowed_paths`, `dependencies`, `body_digest`) are stored as JSON in `events` under `lane_metadata:v1:` (`lanes_meta.go:12-32,67-77`). This provides full auditability without requiring continual table widening for evolving SDD metadata.
- **Out-of-Process Orphan Sweep Subsystem (`internal/serve`)**: `serve` and `lucind-ai run` execute as independent processes against the same SQLite ledger (`explore.md:103-104`). Storing the runner PID in `runs` (`internal/ledger/runs.go:16-24`) allows `serve` to passively verify process liveness across system restarts, terminal kills, and machine sleep without adding an active heartbeat network protocol or coupling runner execution to web serving.
- **Dispatched Packet Traceability**: Sourcing packet markdown directly from the on-disk path captured in `cmd/lucind-ai/cli.go:160-174` and exposing it via `internal/serve` closes the audit gap between high-level dashboard summaries (`internal/serve/model.go:162-184`) and the exact prompt executed by the agent.

## Alternatives Considered & Rejected

- **Two-PR Split (Metadata first, Telemetry + Sweep second)**: Exploration's default recommendation (`openspec/changes/lane-status-observability/explore.md:60-66`) proposed shipping metadata wiring in PR 1 and schema migration/PID sweep in PR 2. Rejected per explicit user override choosing Candidate 1: delivering all six items in one PR under `size:exception` to resolve the 25h+ stuck-lane bug immediately and avoid multi-stage deployment overhead.
- **Metadata-Only Slice**: Considered in exploration (`explore.md:62`). Rejected because deferring telemetry and PID reconciliation leaves the primary operational pain point—zombie `running` lanes after process death—completely unmitigated.
- **Live Executor Skill Telemetry**: Rejected because executors lack a shared "Skill" runtime abstraction (`explore.md:42-47`). Attempting to infer skills from raw prompt text or model output would introduce fragile heuristics.
