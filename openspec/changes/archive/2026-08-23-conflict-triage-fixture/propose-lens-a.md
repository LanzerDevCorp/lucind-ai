## Selected Candidate & Approach

We select **Candidate 1: Two disjoint features + dual-judge rubric** from exploration (`openspec/changes/conflict-triage-fixture/explore.md:17-25`). This delivers the change across two strictly path-disjoint features (`internal/packet/disjoint.go:29-48`) dispatched independently (`internal/run/integrate_feature.go:17,41`):
1. `conflict-triage-agent` (`parent_ref: feature/conflict-triage-agent`, owning `internal/conflicttriage/**`): Implements the advisory conflict triage agent. When `evaluateOverlapGate` (`internal/run/attempt.go:685,687`) triggers `ClassRequired` via `overlap.Classify` (`internal/overlap/overlap.go:622`), `CreateRequest` records overlap evidence and an awaiting reconciliation request (`internal/reconcile/reconcile.go:266,280-300`), setting `AttemptStatusBlocked` (`internal/run/attempt.go:848-856`). The triage agent analyzes the 3-hunk conflict (one business decision, two mechanical controls), isolates the business hunk, labels it ARBITRARY, ratchets risk to `high`, leaves a prepared resolution commit, and states verification cost as wall clock plus command (e.g. `~4 min: ./lucind-checks.sh`). The triage payload is persisted to `reconciliation_candidates.output` (`internal/reconcile/reconcile.go:105`). Unlike autonomous resolution, triage does not fail closed (`internal/resolve/candidate.go:26,303-312`).
2. `conflict-fixture` (`parent_ref: feature/conflict-fixture`, owning `internal/conflicttriage/fixture/`, judge packets, rubric): Implements a reproducible fixture generator that creates real leased features sharing an identical `base_sha` (`internal/feature/feature.go:101-140`). This prevents `overlap.Evaluate` from encountering `overlap.ErrNoMergeBase` (`internal/run/attempt.go:743-747`) and guarantees deterministic `ClassRequired` overlaps (`internal/overlap/overlap.go:93-98,622-660`) to exercise the full operator loop (`cmd/lucind-ai/cli.go:1090-1120,1398-1463`).
3. **Dual-Judge Rubric**: Evaluates triage output quality across heterogeneous executors (`cmd/lucind-ai/cli.go:65-70`), specifically benchmarking `claude`/`claude-opus-5` (`internal/executor/claude.go:35`) against `opencode`/`openai/gpt-5.6-sol` (`internal/executor/opencode.go:53-54`).

This solves the core problem: reconciliation has never fired in this clone (0 `overlap_evidence`, 0 `reconciliation_requests`, and 0 `reconciliation_candidates` in `.lucind/lucind.db` despite 36 integration attempts), leaving overlap handling unexercised. Candidate 1 establishes a reproducible testbed and an actionable advisory triage agent without destabilizing the autonomous merge path.

## Conceptual Changes & Architecture Rationale

- **Advisory Triage vs. Autonomous Merge**: The existing resolver (`internal/resolve/candidate.go:26,303-312`) is designed for autonomous resolution and fails closed on semantic ambiguity (`ErrSemanticAmbiguity`). `internal/conflicttriage` introduces a separate advisory paradigm: it never fails closed, explains conflict etiology, provides a proposed resolution commit, and surfaces business trade-offs with explicit arbitrariness declaration and high risk for rapid (~30 second) operator review.
- **Fixture Merge-Base Invariant**: `evaluateOverlapGate` silently skips overlap evaluation when features lack a common merge base (`internal/run/attempt.go:743-747`). The fixture architecture enforces real ledger-backed features (`internal/ledger/schema.go:131-169`) with a registered common `base_sha` (`internal/feature/feature.go:101-113`), ensuring deterministic promotion blocking and request creation (`internal/run/attempt.go:830-856`).
- **Discrete 3-Band Risk & Wall-Clock Verify Budget**: Triage adopts a discrete 3-band risk model (`low`, `medium`, `high`) rather than a continuous score. Business conflicts are pinned to `high` and cannot be lowered by the agent. Verification cost is expressed as wall-clock duration plus concrete command string, providing actionable operator context.
- **Path-Disjoint Two-Feature Topology**: Splitting agent implementation (`internal/conflicttriage/**`) from fixture generation (`internal/conflicttriage/fixture/`) prevents batch admission errors (`internal/run/integrate_feature.go:17,41`) and isolates fixture harnesses from production agent code.
- **Reconciliation Storage & Promotion Contract**: The triage result payload is stored directly in `reconciliation_candidates.output` (`internal/reconcile/reconcile.go:105`). Operators authorize direction via `reconcile approve` (`cmd/lucind-ai/cli.go:1090-1120`, `internal/reconcile/reconcile.go:406-535`) and register the resolution with `reconcile resolve` (`cmd/lucind-ai/cli.go:1398-1463`). Retry adopts `cand.CandidateSHA` (`internal/run/attempt.go:821-828,870`) and executes compare-and-swap promotion (`internal/integrate/integrate.go:151-173`).

## Alternatives Considered & Rejected

- **Candidate 2 (In-Memory Test Harness + Synchronous Gate LLM)**: Rejected. An in-memory harness without registered features and a shared `base_sha` triggers `overlap.ErrNoMergeBase` and skips overlap classification entirely (`internal/run/attempt.go:743-747`). Moreover, invoking an LLM synchronously inside `evaluateOverlapGate` or `CreateRequest` couples branch promotion to external latency and API failure.
- **Candidate 3 (Public CLI Subcommands: `fixture generate` / `reconcile triage`)**: Rejected as premature. Exposing public commands in `cmd/lucind-ai/cli.go:56` expands CLI surface area before prompts, rubric criteria, and risk formulas stabilize.
- **Failing Closed on Semantic Ambiguity in Triage**: Rejected. Reusing `internal/resolve`'s `ErrSemanticAmbiguity` (`internal/resolve/candidate.go:26,305`) aborts execution rather than presenting a candidate resolution and risk assessment to the operator.
- **Continuous 0–100 Risk Scores & Token/Pricing Metrics**: Rejected. Continuous scores invent false precision for discrete signals; wall clock plus exact command is the only directly measurable and actionable metric.
